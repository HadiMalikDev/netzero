## One-liner

A user creates a project, uploads one or more **Mostadam** manuals, gets a **real extracted checklist** (every credit in those PDFs), fills values and evidence, and asks a grounded assistant “what’s left.”

## The loop (this is the product)

1. Sign in (single account).  
2. Create a project.  
3. Upload one or more Mostadam spec PDFs.  
4. Parser extracts **every credit** it can find in each file → draft checklist.  
5. User reviews / edits the draft (required).  
6. Live checklist: boolean / numeric / text per requirement; attach evidence.  
7. Status is **derived** from values + evidence, not a typed %.  
8. Ask “what’s remaining / what’s missing / what’s overdue” — answers cite the underlying rows.

Hand-entering a credit is a **fallback when a parse fails**, not the setup path.

## Parser

### What “extract” means

Upload a PDF → walk the file → emit **all** credits in it (code, title, keystone, points, aim, numbered requirements, evidence lists, supporting-guidance tables, credit-tool flag, references) plus page/span citations.

HC-10 is **not** the catalog. It is a **known-good check**: after parsing the public Commercial D+C manual, HC-10 must come out as Indoor Air Quality, 3 pts, req 1 = plan + flush-out (1 pt), req 2 = IAQ test (2 pts), Table HC-10.1 limits (formaldehyde 27 / PM2.5 15 / PM10 150 / TVOC 500 µg/m³). Other credits in that file must come out too. If we only ever emitted HC-10, the parser would be fake.

### Deterministic vs AI

| Layer | Job | Must not |
|---|---|---|
| **Deterministic** | PDF text/layout extract; split on credit headers (`HC-10`, `E-01`, …); cut the fixed Mostadam blocks (Aim, Requirements, Evidence, Supporting Guidance, Credit Tool, References); keep page + raw span. | Invent a credit that has no header. |
| **AI** | On an already-cut chunk: guess `metric_type`, tidy broken tables, turn a limits table into numbers. | Add a requirement, point value, or limit that is not in that chunk. |
| **Human** | Confirm / edit the draft. Only then does it become the live project checklist. | Be skipped. |

### Mostadam-only gate

If the file does not look like a Mostadam manual (no credit-code headers, no Mostadam credit layout), **refuse** with a clear error. Do not “best-effort” a LEED PDF into fake Mostadam rows.

### Many PDFs → one project (merge)

- Each upload is a **source document** (file, parser run, raw extract).  
- Credits are keyed by **`(scheme, stage, code)`** — never by code alone. Commercial D+C `HC-10` (Indoor Air Quality) and Commercial O+E `HC-10` (Water Quality) are different rows.  
- Merge = **union** of confirmed credits across the project’s documents.  
- Same key from two files: keep the first confirmed row, **flag a conflict** on the review screen (do not silently overwrite).  
- Category grouping uses the prefix (`HC` → Health & Comfort). No manual department assignment.

### Review screen (required)

Per parse (and again on merge conflicts): list extracted credits/requirements, show source page, allow edit/drop, then **Confirm**. Unconfirmed drafts never drive status or the assistant.

## Checklist & status

**Grain = requirement**, not the whole credit.

| `metric_type` | Input | Done when |
|---|---|---|
| `BOOLEAN` | checkbox | checked |
| `NUMERIC` | number + unit (threshold or bands if the extract has them) | value present |
| `DESCRIPTIVE` | text | text present |

**Evidence:** upload files on a requirement. Stored and listed; not a submission-package export.

**Derived status (credit and requirement):**

- `not_started` — no value and no evidence  
- `in_progress` — some value and/or some evidence, not all requirements satisfied  
- `completed` — every requirement has a value **and** (if the extract listed evidence) at least one attachment  

No points total. No Green→Diamond tier. No owner. No due date. (“Overdue” in the assistant therefore means **incomplete / missing evidence**, not a missed calendar date.)

## Grounded assistant

Scoped to the open project. Retrieval over structured project data + citations. LLM phrases; it does not source truth.

**Stage 1 questions:**

- What’s remaining / what’s left?  
- What documents / evidence are missing?  
- What’s the status of credit `HC-10` / the Health & Comfort category?  
- What’s in progress vs not started?

**Refuse:** inventing a requirement, a point value, or a prediction that is not arithmetic over stored rows. No submission narratives.

## UI — copy SustainIQ exactly

Prototype: https://stick-print-07895563.figma.site/  
Captures: [`../research/reference-site/screenshots/`](../research/reference-site/screenshots/)  
Teardown: [`../research/reference-site/sustainiq-ui-analysis.md`](../research/reference-site/sustainiq-ui-analysis.md)

**Copy exactly** means: same shell, layout, typography, color, components, and screen composition as the screenshots. Do not invent a different visual system. Replace LEED/mock copy with Mostadam/real project data (or empty states). Do not ship the prototype’s fake KPIs (“253 of 513”).

### One intentional product change (looks the same, does something else)

The prototype’s **Certification** wizard step is “pick LEED / Mostadam / EDGE / WELL / BREEAM.”  
Ours is **upload Mostadam PDF(s)** on that step (plus a place to add more PDFs later on the project). Same step slot, different control. That is the setup path.

### What is wired vs chrome

Keep the **full left nav** so the shell matches. Wire behavior only for Stage 1:

| Screen | Stage 1 |
|---|---|
| Login | Wire — one account |
| Dashboard | Wire — KPIs from real projects (counts of projects, credits, missing evidence). No fake charts. |
| Projects list + New Project | Wire — create + list |

| Project detail | Wire — overview from real rollups (status counts, not points/tier) |
| Credits table + credit detail | Wire — core |

| AI Assistant | Wire — grounded queries above |
| Task Board, Reports, Users, Departments, Notifications, Settings | **Chrome only** — match the screenshot; empty or “not in this slice.” No fake demo rows. |

## Data (minimal, multi-tenant-ready)

Single workspace row; every project/document hangs off it. One user. No role table.

Logical objects (not a frozen schema):

- `workspace` (one)  
- `user` (one)  
- `project`  
- `source_document` (PDF + parse job + raw extract + status)  
- `catalog_credit` / `catalog_requirement` (from parse; confirmed flag)  
- `project_credit` / `requirement_entry` (instance: values + derived status)  
- `evidence_doc` (file on a requirement)

Key: `(scheme, stage, code)` on every credit. Parser output is draft catalog; the project instantiates after confirm.

## Out of scope (Stage 1)

- Multi-company SaaS, billing, RBAC, invites  
- Arabic / RTL  
- Non-Mostadam specs  
- Hand-seeding a full Mostadam catalog as the setup path  
- Points engine, keystone rules, Green→Diamond  
- Owners, due dates, task board, notifications  
- Submission-package export / authority submit  
- Generative assistant (narratives, score prediction)  
- Pixel-new design system

## Acceptance (Stage 1 done)

1. Solo login; create a project.  
2. Upload the public **Commercial D+C** manual → draft contains the manual’s credits, not a single hardcoded row.  
3. **HC-10 check:** Indoor Air Quality, 3 pts, two requirements, Table HC-10.1 limits correct, citations point at the source pages.  
4. Upload a **second** Mostadam manual on the same project → union merge; same `(scheme, stage, code)` conflicts are flagged, not silently overwritten.  
5. Confirm draft → live checklist with boolean / numeric / text + evidence upload.  
6. Status moves not_started → in_progress → completed from values + evidence only.  
7. Credits table groups by category prefix.  
8. Assistant answers the Stage 1 questions with citations and refuses to invent.  
9. Shipped screens match the SustainIQ screenshots (layout/components); data is real or empty, never prototype mock LEED numbers.  
10. Non-Mostadam PDF is rejected.
